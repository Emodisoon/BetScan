# Bet Scan: контекст и правила проекта

## Договорённости с пользователем

- Java 25, Spring Boot, Playwright Java.
- Источники: https://betboom.ru/ и https://pari.ru/.
- Только футбол, только прематч, только 1/X/2 за основное время (90 минут + добавленное).
- Пользователь подтвердил: сайты не откроются из текущего окружения. Сейчас нужна базовая
  реализация; пользователь запустит её в другом окружении и пришлёт диагностику.
- Не считать интеграции проверенными до получения реального DOM и успешного обхода.
- Сейчас отсутствуют реальные селекторы обоих сайтов. Это намеренно: первый запуск
  диагностический, с `NEEDS_CONFIGURATION` после успешной загрузки страницы.
- Все важные изменения архитектуры, запуска и ограничения поддерживать в этом файле.

## Стек и запуск

- Maven 3.9+, JDK 25, Spring Boot 3.5.16, Playwright Java 1.58.0.
- Java 25 должна использоваться и Maven, и `java -jar`. Проверять `mvn -version`.
- В исходном окружении JDK 25 есть в `%USERPROFILE%\.jdks\corretto-25.0.1`, но системный
  `java` по умолчанию — Java 8. Не зашивать локальный путь в сборку.
- При необходимости в PowerShell:

```powershell
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\corretto-25.0.1"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
mvn verify
mvn exec:java '-Dexec.mainClass=com.microsoft.playwright.CLI' '-Dexec.args=install chromium'
java -jar target/bet-scan-0.1.0-SNAPSHOT.jar
```

- Linux: установка Chromium с зависимостями — `-Dexec.args="install --with-deps chromium"`.
- `.mvn/maven.config` выбирает `.mvn/settings.xml`, использующий Maven Central напрямую.
  Это изолирует проект от пользовательских корпоративных mirrors; глобальные настройки не менять.
- Для уже установленного Chrome: `SCANNER_BROWSER_CHANNEL=chrome`. По умолчанию используется
  Chromium Playwright. Edge: `msedge`. При обновлении Playwright переустановить браузер.
- Для видимого окна: `SCANNER_HEADLESS=false`. По умолчанию браузер headless.
- Сервер по умолчанию доступен только локально, без авторизации. `SERVER_ADDRESS` и `PORT`
  меняют bind/порт. Не включать открытый внешний bind по умолчанию.

## Архитектура

- `config/ScanProperties`: валидируемые параметры, профили DOM по `Bookmaker`.
- `model/MatchOdds`: неизменяемый снимок 1X2 одного матча одного букмекера.
- `scraper/BookmakerScraper`: граница браузерного сбора, результат с признаком частичности.
- `scraper/PlaywrightBookmakerScraper`: открывает футбольные страницы, ждёт DOM, извлекает
  строки, прокручивает выбранный контейнер, дедуплицирует по пути URL события.
- `extract-rows.js`: читает строку атомарно в JS, каждый селектор поля обязан найти ровно
  один элемент. Селекторы полей — CSS относительно строки; `row`/`ready-selector` — Playwright.
- `scraper/QuoteParser`: десятичные коэффициенты и время, независим от браузера.
- `scraper/Diagnostics`: последний HTML/скриншот/DOM/отчёт для каждого источника.
- `service/ScanService`: один worker, атомарные снимки, расписание, предотвращение наложений.
- `api/ScanController`: `GET /api/matches[?bookmaker=PARI|BETBOOM]`, `POST /api/scans`.
- Playwright/Browser/Context/Page создаются, используются и закрываются в одном worker-потоке.
  Не хранить Page как singleton и не передавать между потоками.
- Каждый источник использует новый анонимный BrowserContext; cookies/storage state не сохраняются.
- Нет БД, истории коэффициентов, сопоставления событий между БК, UI, live и размещения ставок.

## Семантика данных и ошибок

- `eventId` — путь URL события в пределах букмекера. Глобальный ключ: bookmaker + eventId.
- `home`, `draw`, `away` — BigDecimal > 1. Нет округления через double.
- Строки с неоднозначными/отсутствующими полями, заблокированными коэффициентами и
  неизвестным временем пропускаются, источник получает PARTIAL при наличии других матчей.
- Селекторы коэффициентов должны явно ограничивать рынок 1X2 основного времени.
  Нельзя брать первые три числа карточки: это могут быть форы, тоталы или таймы.
- `row` обязан ограничивать футбольный прематч. Одного будущего времени недостаточно,
  если DOM содержит другие виды спорта; это проверяется при настройке профиля.
- Время сайта без offset трактуется как Europe/Moscow, браузер использует эту же зону.
  Поддержаны ISO datetime, `Сегодня/Завтра [в] H:mm`, `dd.MM.yyyy HH:mm`,
  `d MMMM yyyy HH:mm`. Даты без года не угадывать. Добавлять форматы по реальным примерам.
- `startsAt <= observedAt` запрещено; при чтении API уже начавшиеся матчи тоже скрываются.
- NOT_SCANNED — нет попытки; SUCCESS — выбранные строки обработаны до конца прокрутки;
  PARTIAL — лимит/отброшенные строки; ERROR — не удалось получить пригодный снимок.
- SUCCESS не гарантирует всю линию букмекера: свёрнутые турниры, вкладки/пагинация пока
  не обходятся. Дополнить обход после изучения реальных страниц.
- Нулевой результат считается ошибкой; подтверждённое состояние «матчей нет» ещё не реализовано.
- При ERROR последний успешный снимок и lastSuccessAt сохраняются. `stale` вычисляется
  отдельно по времени (10 минут), поэтому ERROR может сопровождаться `stale=false`.
- При PARTIAL публикуется только новый частичный снимок. Старые и новые цены не смешиваются.
- Обновление источников независимо: ошибка BetBoom не мешает попытке PARI.
- `/actuator/health` проверяет Spring, не букмекеров. HTTP 200 у `/api/matches` не означает,
  что источники доступны: проверять `sources[].status`, `stale`, `lastSuccessAt`.

## Конфигурация

Базовая: `src/main/resources/application.yml`. Локальная: `config/application.yml`
(gitignored, Spring загружает из рабочего каталога). `config/application.example.yml`
показывает синтетический контракт, НЕ реальные селекторы. Не подключать пример как рабочий профиль.

| Параметр scanner | По умолчанию | Назначение |
|---|---|---|
| enabled / SCANNER_ENABLED | true | Автообход; ручной POST работает и при false |
| interval-ms / SCANNER_INTERVAL_MS | 300000 | Интервал вызова планировщика, занятые вызовы пропускаются |
| initial-delay-ms | 5000 | Задержка первого автообхода |
| headless / SCANNER_HEADLESS | true | Без окна |
| browser-channel / SCANNER_BROWSER_CHANNEL | пусто | Chromium Playwright или chrome/msedge |
| proxy / SCANNER_PROXY | пусто | Прокси Playwright, например http://host:port |
| timeout-ms | 30000 | Навигация/ожидание селекторов |
| settle-ms | 1500 | Ожидание после прокрутки |
| max-scrolls | 60 | Ограничение обхода виртуальных списков |
| max-matches | 3000 | Ограничение количества событий на источник |
| stale-after-ms | 600000 | Порог устаревания |
| diagnostics-directory / SCANNER_DIAGNOSTICS_DIRECTORY | diagnostics | Диагностика и лог |

Профиль `scanner.sites.BETBOOM` / `PARI`:
`url`, `ready-selector`, `row`, `home-team`, `away-team`, `start-time`,
`start-time-attribute` (по умолчанию datetime; пусто = текст), `event-link`,
`home-price`, `draw-price`, `away-price`, `live-marker`, `scroll-container`.
Пустой scroll-container означает document.scrollingElement.
Все поля кроме ready-selector/live-marker/scroll-container/start-time-attribute обязательны
для извлечения. До заполнения селекторов сохраняется диагностическая страница.

## Диагностический цикл с пользователем

1. Запустить приложение в сети, где сайты открываются.
2. Выполнить `./scripts/collect-diagnostics.ps1` в другом терминале.
   Скрипт вызывает POST, ждёт завершения и упаковывает diagnostics.zip.
   Параметры: BaseUrl, DiagnosticsDirectory, TimeoutSeconds, OutputPath.
3. Получить от пользователя архив. Для каждого источника нужны page.html, page.png,
   dom.json, report.json; общий application.log и api-status.json.
4. Если запуск браузера/навигация не удались, часть файлов отсутствует; читать report.json.
   Наличие NEEDS_CONFIGURATION — ожидаемый результат первого успешного открытия.
5. По реальному HTML настроить/закоммитить рабочие профили в application.yml, при необходимости
   выделить отдельные адаптеры сайтов. Проверить вкладку «Прематч», заголовки рынка, live,
   свёрнутые турниры, даты, вложенные scroll containers и виртуализацию.
6. Добавить обезличенные реальные fixtures и регрессионные тесты. Не выдавать синтетические
   fixtures за подтверждение совместимости с сайтом.
7. Повторить обход у пользователя и сверить несколько матчей/коэффициентов с UI.

Диагностика перезаписывает последние файлы каждого источника. Логи ротируются (5 MB, 2 дня).
Скрипт создаёт датированную копию в diagnostics/bundle-* для упаковки. Не коммитить диагностические
архивы, браузерные профили, пользовательские данные. Cookies/headers специально не записываются;
HTML всё равно следует просмотреть перед публичной публикацией.

## Проверки и дальнейшая работа

```powershell
mvn verify
# Дополнительный тест извлечения DOM в настоящем локальном браузере, без внешних сайтов:
mvn verify '-Dplaywright.tests=true' '-Dplaywright.channel=chrome'
```

- Обычные тесты не требуют установленного браузера и доступа к сайтам.
- QuoteParserTest: коэффициенты, локальное время, смена года, невалидные/начавшиеся события.
- ScanServiceTest: сохранение снимка при сбое, независимость источников, отсутствие наложений.
- ScanControllerTest: Spring context, API, фильтр букмекера, невалидные параметры.
- DomExtractionTest: синтетический DOM, три точных исхода, live и неоднозначные селекторы.
- После правки парсинга запускать соответствующие тесты и `mvn verify`.
- Не обходить CAPTCHA/геоблокировки: сохранять диагностику и сообщать ошибку источника.
- Не добавлять новые виды спорта/рынки, БД или UI без согласованной задачи.

Проверено 2026-11-16: `mvn verify -Dplaywright.tests=true -Dplaywright.channel=chrome`
на Corretto 25.0.1 — 22 теста без ошибок; executable jar собран. Отдельно проверены
запуск jar, `/actuator/health` и упаковка архива скриптом на локальном порту 18080
с намеренно неверным browser-channel (проверка диагностики ошибки запуска, без обращения к БК).
Работоспособность на реальных сайтах пока не проверена.
